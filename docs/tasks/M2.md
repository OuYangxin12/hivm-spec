## 4. 设计要点（开工前约定，防走样）

1. **D6 复用遍历核**：T2.1 与 T3.2 共用一个遍历核心；核心层不得 import `bishengir`。
   时序引擎消费 `VModule`（含 `VSync`），与占用引擎平级——**不许**为时序另写一条
   MLIR 遍历。
2. **结构判定与观测分离**（T2.3 vs T2.1/T2.2）：结构性死锁（wait 引用的事件无人
   set、或 wait-for 图成环）是**不依赖策略探索的确定性结论**，必须与"探索策略下
   未发现"严格分层输出，后者永远带策略集限定语。
3. **展开界的诚实口径**：循环 trip 未知时按展开界截断，结论必须携带"截断"限定；
   静态 trip（如 preload 的 `c4`）不截断。
4. **计数配平 ≠ 顺序可行**：L0 语料 `waits_before_sets_deadlock` 是本项目的立论
   案例之一（FileCheck 必然漏过）。T2.3 的最小验收就是它。
5. **multi_buffer 与时序**：`hivm.multi_buffer=N` 意味着 buffer 的 N 个槽位在流水线
   上交替——时序图需按槽位区分，否则会出现虚假的 RAW 依赖。T2.4 渲染时处理。
6. **预算**：D10 表 timeline ≤30s/kernel；探索策略 × 展开界组合爆炸时先降展开界，
   不删策略（止损：删能力不可逆，降界可逆）。

## 5. 风险与止损

| 风险 | 触发信号 | 处置 |
|---|---|---|
| VIR 缺时序所需信息（如 op 耗时模型） | T2.1 建模受阻 | M2 只做**事件序与依赖**，不做绝对耗时（耗时模型属 M3+）；甘特图用"事件步"而非时钟 |
| 策略组合爆炸 | 30s 预算超标 | 先降展开界（记入结论限定语），再砍策略；都救不了 → 上报（D1 复查条款） |
| `scope.scope`/嵌套 region 内同步语义不确定 | preload 家族 verdict 反常 | 以下游可见性最保守解释（scope 出口才可见），登记 D9 漂移，不得反推 |
| VIR 契约需扩展（如 VSync 增字段） | 破坏性变更 | 框架 §6.1 版本化条款：同步全部消费引擎 + 本卡记录变更理由 |
| **需上报决策** | ① 结论 schema 无法同时表达结构层与探索层；② cv kernel 存在引擎无法解释的真实同步形态；③ 预算需上调 | 停下，写清证据后交用户决策 |
