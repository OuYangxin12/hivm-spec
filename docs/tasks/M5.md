## 0. 为什么做这一程

该案例实测暴露了一个**六项检查全盲**的缺陷类别（实测记录见本卡 §5）：

| 检查 | 在该 IR 上的结论 | 为什么没抓到 |
|---|---|---|
| `ub_occupancy` | COVERAGE_GAP | 与缺陷无关，且该 IR 有未建模路径 |
| `timeline` | COVERAGE_GAP | 同上；缺陷不是同步问题 |
| `sync_pairing` | OK | 正确——不是配对缺陷 |
| `uninit_read` | **OK（漏报）** | 失败形态是"被零填充顶替"，不是读未初始化；且手动制造真·读未写后仍报 OK——未建模 op 被「保守视为已写入」吞掉 |
| `equivalence` | COVERAGE_GAP | 值语义链在 `mmadL1` 逃生舱 / `linalg.matmul`（社区方言不建节点）处断链；输入为 `?` 动态维推不出 |

结论：**要覆盖这一类，不能只靠值等价**。缺的是一项**结构级**检查——它不执行值语义、
不需要输入、不需要锚点，只问一个问题：

> **这个矩阵乘的输入槽位，有没有真实的数据来源？**

该问法对 layout 代数（mmadL1 逃生舱的根因）**免疫**——我们不需要算分形布局，
只需要判定"输入是不是一个编译期常量零 / 一个从未被写过的 buffer"。

## 1. 目标与非目标

**目标（本程交付）**
1. 新检查 `operand_wiring`：对矩阵乘族 op 的 **DPS 输入槽位**（不是 init/累加器槽位）
   判定数据来源，检出两类形态：
   - **R1 `wiring/neutralized-input`**：输入槽位是**编译期零常量**（`linalg.fill` 零 /
     `arith.constant` 零 splat），即该输入不含任何数据来源；
   - **R2 `wiring/dataless-input`**：输入槽位经纯视图链（view/cast/`to_tensor`）到达
     `tensor.empty`，即读了内容未定义的张量。
     > **实施期收敛（记录）**：原计划的另一半"到达无写者的 buffer"**未实现**。
     > 原因：V→C 成对 cbuf 是两个不同 SSA、由 transfer 标注配对，朴素的"谁写过这块
     > buffer"会把它判成"没人写"→ 在**正确**的 IR 上误报（FR2 第一压制目标）。
     > 要做对必须先建跨核配对同一性模型，已登记为 §4 缺口 4。
2. 覆盖矩阵乘族：`linalg.matmul`、`hivm.hir.matmul`、`hivm.hir.mmadL1`、
   `hivm.hir.mix_matmul`、`hivm.hir.batchMmadL1`（前者用于 ttadapter 层，后四者用于 npuir 层）。
3. **在真实案例上可复现的检出**：失败版报 MISMATCH 并定位到 dot 的 B 槽与源码 loc；
   修复版报 OK。
4. 零值出现在 **init 槽位**一律合法（零累加器是常态）——这是本检查精度的关键，
   也是它与"看到 fill 就报警"的朴素做法拉开差距的地方。

**非目标（明确划出，避免本程失控）**
- 不实现 `mmadL1` 的值语义（仍是逃生舱；那是 M6 候选，见 §4）；
- 不做输出值对拍 / 步数不齐的等价模式（M6 候选）；
- 不解决 Triton ABI 动态输入推导（`memref<?xi8>` → f32 视图）；
- 不改 `uninit_read` 的保守口径（它的「未建模即视为已写」是刻意的假阳性压制，
  本程用**独立检查**覆盖它漏掉的那一类，而不是放松它的口径）。

## 2. 设计

### 2.1 判定口径（为什么这样定才是"可证"的）

- **R1 可证**：输入槽位的值是编译期零 → 该乘法的贡献恒为 0。零出现在输入槽位只有两种解释：
  源码确实乘零（退化但合法）或 pass 把丢失的操作数兜底中和了。为兼顾 FR2（假阳性是
  第一压制目标），诊断文本必须**显式给出这两种解释与消除办法**（源码确实乘零时在 op 上
  加显式标注），不得只报"错误"。
- **R2 可证**：输入槽位的数据源 buffer 在全模块没有任何写者 → 读的是未初始化数据。
  保守方向沿用 `uninit_read` 的口径（未知 op 保守视为有写者），因此 R2 只在链上
  op 都已建模时才发声；被保守放行时**必须留痕**（notes 里报"因未建模而可能漏报"）。

### 2.2 存放位置（D6：唯一遍历核）

结构事实由**引擎**在唯一遍历中收集（`VModule` 的新增只读字段，加载期填充）：

- `VNode.dps_input_count`：该 op 的 DPS 输入槽位数（0=非矩阵乘族），引擎按 op 家族填充；
- `VModule.structure`：结构级只读事实（`defs`：SSA→定义 op 名；`zero_values`：编译期零的 SSA；
  `writers`：SSA→写它的 op 名集合）。**不承载值语义**——值语义仍走描述库。

检查模块 `src/hivm_spec/wiring.py` 只消费 `VModule`（不碰 MLIR），故可离线单测。

### 2.3 接入点（沿用既有封闭集合，M4 §10.2 的教训：新类别要动 5 处）

`spec.py::KNOWN_CHECKS` · `generate.py` schema enum · `__main__.py::_IMPLEMENTED_TOOLS` ·
`assemble.py::_TOOLS`（+ `run_tool` 的报错文案） · `run_checks.py` 全跑清单 · `specs/cv.py` 的 check 声明。

## 4. 本程不做但必须登记的缺口（M6 候选）

1. **`mmadL1` 值语义**（逃生舱）——等价验证 36/41 缺口的主因；
2. **输出值对拍模式**（结构性大改前后步数必然不齐，现口径直接报缺口）；
3. **Triton ABI 输入推导**（`?xi8` → f32 视图），或由 agent 用真实用例参数喂入（S4/Q10）；
4. **R2 的盲区**：链上出现未建模 op 时保守放行——把"未知 op 是否写了这块 buffer"
   提升为可判定（需要 op 读写集，工作量大，收益是让 R2 在 npuir 层更常发声）。

且定位到"哪个 op 的哪个输入槽位"与源码行（FR5）——"已确证的问题优先于别处缺口"
的聚合口径（`run_checks._BLOCKERS`）保证它不会被 COVERAGE_GAP 掩盖。

未覆盖/未验：npuir 层的同类 IR 需正确的 target env 才能被 dialect verifier 接受

## 6. 风险与止损

| 风险 | 触发信号 | 止损 |
|---|---|---|
| 假阳性（把合法的零输入判为缺陷） | 语料 L0/L1/L2 上出现 R1 命中而人工复核为合法 | 收窄 R1：追加"零值与本 op 同源/同块"要求；或降级为 warning + 结论口径改为 COVERAGE_GAP |
| R2 因未建模链而不发声成为摆设 | 真实注入例全被保守放行 | 明确写入边界文档（不假装能查），把 R2 的增强登记为 §4 缺口 |
| 引擎追加字段破坏既有不变量 | 不变量单测/语料回归失败 | 字段保持默认值 + 纯追加；失败即回滚 T5.2 |
| 覆盖判定被误读为"这 IR 没问题" | 报告未带边界说明 | 报告必须带 notes（保守放行项、未建模项、槽位口径） |
