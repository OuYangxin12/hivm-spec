## 0. 为什么这是最重要的一程（读之前先明确）

M1/M2 交付的是**状态视图工具**（UB 占用图、时序图），定位是"调试辅助"。
真正对应最痛缺口 G1、且在 `requirements.md` 里被列为 **P0 的 FR1（语义等效）**
到 M2 结束仍是零兑现。D8 因此把**最小等价内核**钉为**不可裁剪交付底线**：

> 具体执行差分（固定种子输入）+ 逐 op 值哈希 trace + 首发散点定位
> （T3.1/T3.2/T3.5/T3.6）——范围可缩（op 子集、静态 shape、单 kernel），
> **但该能力不得整体删除或无限延期**；若延期须在框架 §3 D8 显式记录理由与
> 新兑现时点，而非默认顺延。

M3 的成败判据不是"工具能跑"，而是**注入一个语义缺陷能否被检出并定位到首个
发散的 op**（AC1 语义维）。

## 4. 设计要点（开工前约定，防走样）

1. **D12 单输入 vs 差分对拍的张力**——必须先想清楚。D12 规定"每个工具恒吃
   一份 IR"，而 T3.5 的差分天然需要 before/after 两份。口径：`equivalence`
   工具的**主输入仍是一份**（待验证 IR），锚点通过**显式独立参数**给出
   （如 `--anchor before.mlir`），而非把两份 IR 混作位置参数。理由：保持
   "位置参数恒为一份 IR"的 CLI 契约不破，同时让"谁是被验证对象"在命令行上
   一眼可辨——这直接关系到 verdict 归属谁。
2. **锚点缺失不得静默降级为"自比"**。没有锚点时 verdict 必须是
   `COVERAGE_GAP` 或 `PENDING`，**绝不能**拿同一份 IR 自比后报 OK——那是
   最典型的自欺形态（FR4/NFR2）。
3. **容差不是"调到通过为止"的旋钮**。rtol/atol 必须在**描述**里声明
   （全局 + per-op 覆盖），进 `spec_hash`；结论中必须回显实际生效的容差值。
   禁止 CLI 临时放宽容差——那等于允许用命令行参数消灭一个真实的 MISMATCH。
4. **值哈希必须对"结构不同但语义等价"稳健**。哈希对象是**值内容**
   （dtype + shape + 归一化字节），不含 op 名、SSA 名、位置——否则任何合法
   变换都会假发散。定点/浮点分别处理：浮点在容差内视为相等，故哈希用于
   **定位**，判等仍走容差比较（哈希只做快速筛选，不做最终裁决）。
5. **首发散点 = 拓扑序上第一个超容差的节点**，报告须给出 op、`Loc`、用例
   种子、前后值摘要。同一发散会沿数据流传播成一大片，只报首现 + 影响计数
   （与 M2 死锁诊断去重同一原则：FR5 可定位 且 不淹没摘要）。
6. **未建模 op 一律 `COVERAGE_GAP`，不得"跳过后继续对拍"**。跳过一个 op 再
   比较后续值，等于宣称"我不懂的那步不影响结果"——这是无依据的。
7. **性能预算的处置边界（D1）**：T3.7 超限只允许替换**执行核**，不得改动
   DSL 或生成器契约。若发现瓶颈在 DSL/生成侧，须作为设计问题记录，不得
   顺手重构。
8. **规则 C 的 M2 遗留**：跨泳道饥饿判定目前只在**无截断**时可用（动态 trip
   即降级）。M3 若引入"每迭代供需差"的归纳论证（trip 无关），归属 timeline
   引擎增强，不并入等价验证范围——避免 M3 范围膨胀（D8 要护的是最小内核）。

## 9. 语义决策与漂移登记（D9 候选）

1. **锚点缺失 → COVERAGE_GAP，绝不自比**。`compare()` 要求两个 `ExecResult`，
   无单参数退化模式，并用 `inspect.signature` 锁定该 API 形状。理由：自比恒等于
   "通过"却什么都没验证，而报告上的 OK 与真验证过的 OK 无法分辨（FR6）。
2. **判等走容差，哈希只做筛选与定位**。两步：① 逐步比哈希找候选（快）；
   ② 容差裁决（准）。只做 ① 会把容差内正常抖动报成 MISMATCH；只做 ② 则说不清
   "从哪一步起不等"。容差**只来自描述**并进 `spec_hash`，不接受 CLI 覆盖——
   那等于允许用命令行参数消灭一个真实的 MISMATCH。
3. **`INITIAL_ARM=1` 保留，假设改写为"主仓不依赖初始装载"**（T3.0）。对拍主仓
   C++ 链后确认：主仓未对 flag 初态做依赖性假设，故本模型在方向上压制假阳性
   （NFR2）成立。风险等级已下调。详见 `docs/crosscheck/T3.0-flag-semantics.md`。
4. **`round_mode` 的 `ROUND` 是 tie-away-from-zero，不是 `np.round`**。后者为
   tie-to-even。已用编译的 C 参考程序逐值比对确认。这类"名字相同语义不同"的
   陷阱若不显式对拍，会安静地产生错误结论。
5. **`bf16` 缺 `ml_dtypes` 时报错，绝不降级为 f32**。降级会让"没有 bf16 支持"
   伪装成"bf16 验证通过"。未知 dtype 后缀同样不默认 f32。
6. **未建模 op → COVERAGE_GAP 且带原因**，不"跳过继续比"。"没发现发散"可能只是
   因为没算那一步。同理：两侧步数不同不挑能对上的部分比（自选有利证据）。
7. **输入面 = `VFuncArg`（全部函数参数），与 `allocs` 分离**（T3.7 修正）。
   `allocs` 只收带 `#hivm.address_space` 标注的参数，那是占用分析口径。合并会
   二选一地制造假阳性（占用把 host 内存算进片上）或假缺口（等价推不出输入）。
8. **`VTrace` 是逐 op 值哈希的唯一落点**（T3.6 修正）。T3.2 曾自建 `OpTrace`
   并行结构，`VTrace` 零使用——已接回契约，`OpTrace` 降为内部累积。未建模的步
   **也发事件**（`mode="unbound"`），否则消费者会把"没算"读成"算过且一致"。
9. **截断语义继承 M2**：一份 IR 不得有两套"验证到多远"的说法。
