# 任务卡 M1：UB 占用图（首个 spec 工具）

> **状态**：📋 已就绪，未开工
> **目标**：`hivm-spec tool ub_occupancy <ir.mlir>` 产出峰值占用图与 OVERFLOW/OK 判定
> **前置**：M0 ✅（VIR 契约 / Spec DSL / 生成链路 / 语料 L0+L1）
> **退出标准**：双 kernel 出图且在 **≤10s** 预算内（D10/AC2）；注入缺陷被检出（AC1 溢出维）

本卡是 `milestone-plan.md` §3 的执行视图。M1 是**第一个真正产出结论的里程碑**——
在此之前所有产物都是内部结构；从这里开始，工具的输出会被 agent 当作判断依据。
因此本卡的止损条件比 M0 严格：宁可缩小范围，不可让结论"看起来可信"。

## 1. T1.0 gap 分析（已完成，作为本卡的输入）

目标 kernel 实测（主仓 commit `80db8e8c`）：

| kernel | 行数 | 唯一 op | 已建模 | 待建模 | scf.for | memref.alloc |
|---|---|---|---|---|---|---|
| `cv-pipelining.mlir` | 1168 | 11 | 3 | **8** | 78 | 46 |
| `cv-pipelining-preload.mlir` | 170 | 7 | 2 | **5** | 5 | 4 |

**待建模 op 合集（9 个，按频次）**：
`mmadL1(26)`、`fixpipe(26)`、`vexp(20)`、`copy(12)`、`nd2nz(2)`、`set_atomic(2)`、
`vcast(2)`、`debug(1)`、`vbrc(1)`

**关键判断**：这 9 个 op 中只有 `mmadL1` 需要逃生舱（spike 已确认），其余 8 个的
**效应**都可声明式表达。M1 只需效应级建模（D3），故 gap 是可控的——这印证了
D13 "前 20 个 op 覆盖 82.2%" 的取样结论。

> **提醒**：`cv-pipelining.mlir` 含 `split-input-file`，属 L2 语料，
> 入库前必须按 D13 做夹具剥离并登记 manifest。

## 5. 风险与止损

| 风险 | 触发信号 | 处置 |
|---|---|---|
| ~~**bindings 环境不可得**~~ | ~~本地/CI 无 cp310 绑定~~ | **已解除（T1.1 实测）**：绑定树可整体拉到本地，`scripts/setup_bindings.sh` 已固化（须 `rsync -azL`，见框架 §6.2）。本地 py3.10 + bindings 全量 **160 passed**。公共 CI 仍无绑定，故 `requires_bindings` 跳过机制保留 |
| 动态 shape 导致占用无法判定 | 大量 `UNKNOWN_SIZE` 缺口 | 输出 `COVERAGE_GAP` 而非猜测尺寸；实测 123/189 语料含动态 shape，故这是**常态**，不是失败 |
| 生存期语义与真实分配器不符 | 手算对不上 | 先按顺序语义（保守）；差异登记 D9 漂移，**不得**为对齐结果反推语义 |
| 10s 预算超标 | T1.7 实测超时 | 先缩范围（减策略数/降展开界），不得删能力；实测值必须回填 D10 表 |
| `mmadL1` 逃生舱扩散 | 逃生舱条目 >2 | 停下重估：逃生舱多意味着 DSL 表达力不足，属需上报的架构信号 |

> **需上报决策的情形**：① 逃生舱条目 >2；② 生存期语义与真实分配器有系统性偏差；
> ③ 10s 预算需上调；④ VIR 契约需破坏性变更（框架 §6.1 要求同步全部消费引擎）。

## 6. 与 M0 的衔接点

- **VIR 是唯一入口**：T1.2/T1.3/T1.4 只消费 `VModule`，不接触 MLIR（D6）；
- **trust 降级必须体现**：toy 描述当前全部 `provisional`，故 M1 的一切结论都须带
  降级标注（FR6）——不能因为"图画出来了"就让结论看起来权威；
- **绊线会动**：新建模 9 个 op 后覆盖率从 7.9% 升至约 16%，须在 PR 中可见。
