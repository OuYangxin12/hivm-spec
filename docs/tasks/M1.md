## 5.5 L1 实跑暴露的四个缺陷（T1.1/T1.4 补强）

把 10 份 L1 语料真正跑一遍后暴露四处缺陷，**全部属"工具给出貌似正常的结论，
实际什么都没分析"**——即本项目最该防的假阴性。

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | 配置文档键名 `options`，assemble 读 `params` | `spaces_of_interest` 恒空，静默退化为"分析恰好存在 alloc 的空间"；声明要查的 space 若无 buffer 则**根本不出现在结果里** | 统一为 `options`，加测试锚定生成器与消费者的键名一致 |
| 2 | 零 buffer 仍给 `OK` | **最危险的假阴性**：`annotate-vf-alias.mlir` 拿到干净绿灯，而工具一个 buffer 都没找到。"安全"与"无知"外观完全相同 | `is_vacuous` 判据 → 降级 `COVERAGE_GAP`，并明说"不代表不溢出，而代表未能分析" |
| 3 | 函数参数形态的片上 buffer 被忽略 | 该 kernel 的 3 个 UB buffer（各 256B）全是 `func.func` 参数而非 `memref.alloc`，占用被算作 **0** | 新增 `AllocOrigin.FUNC_ARG`；生存期覆盖全函数（调用方持有），不报"未见访问" |
| 4 | 内层 `builtin.module` 不下钻 | `module attributes {dlti.target_system_spec = ...}` 是主仓常见包裹形态；不下钻则**整个内层 module 的全部函数不可见**，VIR 为空、指纹为空串哈希，引擎却照样产出结论 | `builtin.module` 纳入 `REGION_KINDS` |

附带修正：无 `#hivm.address_space` 标注的 `memref.alloc` 原被**静默丢弃**，
违反 FR4。改为登记缺口并说明后果（"若它实为片上 buffer，占用将被低估"）。

**方法论教训**：这四处没有一个能靠读代码或写手写 VIR 发现——手写 VIR 天然
只包含我已经想到的结构。**必须拿真实语料跑真实链路**。

### L1 全量实跑结论（10/10）

| verdict | 份数 | 说明 |
|---|---|---|
| `OK` | 2 | 均确实分析到 buffer（768B / 96B），非空洞 |
| `COVERAGE_GAP` | 8 | 未建模 op（fixpipe/debug/mmadL1/set_mask_norm 等）或无片上 buffer |
| 误报 | **0** | 无虚假溢出 |

守卫已固化：`test_no_l1_case_yields_a_vacuous_ok` 遍历全部 L1，任何 `OK`
都必须真的分析到 ≥1 个 buffer。

## 8. L2 收割与目标 kernel 验收实录（T1.0/T1.0b/T1.7）

### 收割（scripts/harvest_corpus.py，可审计剥离）

主仓 `cv-pipelining.mlir`（1168 行，**18 个 split-input-file 分节**）+ `cv-pipelining-preload.mlir`
（170 行）→ **19 份 L2 语料**，逐条留档。剥离内容（写入 manifest `extraction`）：

1. lit 指令行与整行注释；
2. `"some_op"` 生产者占位符**按类型定向替换**：标量→`arith.constant`、tensor→`tensor.empty`、
   **memref→提升为函数参数**（不能用 `memref.alloc` 顶替——那会凭空增加分配，破坏占用语义）；
3. `"consume"` 类消费者占位符剥离（无结果无分配，消费的 SSA 值变为未使用，合法）；
4. 每份入库前经真实 bindings **严格解析**（不开 allow_unregistered），解析不过不入库。

占位符是 pass UT 作者为让 pass 有输入而造的"值发生器"，属**夹具细节**而非 kernel
语义——与 D13 拒绝批量导入的理由同源：夹具细节不得污染语料库。

### 建模（specs/cv.py，ODS 真值而非用例反推）

9 个 op 全部建模，pipe/效应均引 `HIVM*.td` 证据：

- `mmadL1`：`cond_wr(out, when=init_condition)`（ODS："condition under which data in
  L0C is cleared before use"）+ **逃生舱恰 1 个**（分形布局代数）；
- `fixpipe`=PIPE_FIX、`nd2nz`=PIPE_MTE2、`vexp/vcast/vbrc`=PIPE_V；
- `set_atomic`：改"后续 GM 写"的原子模式，无 buffer 效应——用声明式 value 表达
  （静态检查拒绝零效应零值语义的空描述，FR4，正确地拦了一次）；
- `debug`：ODS 为 MemRead+MemWrite，效应级只建模读（保守：读延长生存期）。

合并机制：`Spec.merge` + `gen` 多文件——真实 kernel 需要的是描述**并集**
（toy 的 load/store/vadd + cv 的 9 op），重名冲突报错而非静默覆盖。

### 诚实的缺口形态（不是失败，是结论的一部分）

verdict 全部为 `COVERAGE_GAP`，原因属三类**结构性**情形：

1. **tensor 化 fixture**：早期分节的 hivm op 走 tensor 形态（pre-bufferization），
   `#hivm.address_space` 在类型上不可见——效应空间在**这份 IR 层面**确实欠定，
   工具不猜（每处效应一个缺口，指明 op 与原因）；
2. **未标注 alloc**（`memref<16x16xf16>` 无空间标注）：记缺口并说明"若实为片上
   buffer，占用将被低估"，峰值按**下界**理解；
3. **preload kernel 的 `effects=["write","read"]` 与 `tightly_coupled_buffer` 标注**：
   前者是 T1.3"标注优先"尚未消费的效应标注（**遗留 → M2**），后者记入引擎提示。

> **结论口径**：M1 的验收是"出图 + 预算内 + 缺口诚实可解释"，不是"全绿"。
> 在 pass UT 的 IR 层面给出 OK 才是可疑的——那需要猜空间。
